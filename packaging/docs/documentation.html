Finbolt documentation

A payments and fintech marketing template. Ten pages, one stylesheet, one script, no build step and no dependencies — plus a matching WordPress theme in a separate package.

1. Getting started

Open template/index.html in a browser. There is nothing to install.

If you add anything that fetches a file over http, serve the folder instead of opening it directly:

cd template
python3 -m http.server 8000
# then open http://localhost:8000

Deploying

Any static host works — Netlify, Vercel, Cloudflare Pages, S3, or plain shared hosting. Upload the contents of template/ to your web root. For GitHub Pages, push the folder and set Settings → Pages → Deploy from a branch.

3. Editing the HTML

Pick one of two routes and stick to it.

Choose before you start. The pages are generated by build.py. If you hand-edit the HTML and later run the script, it overwrites your work. Editing HTML directly is perfectly fine — just delete build.py first so it cannot bite you.

Route A — edit the HTML

Every page is plain, indented HTML with no templating. Header, footer and CTA markup repeat on each page, so a change to any of them means editing ten files. Delete build.py.

Route B — edit the build script

Better while the site is still changing shape: one edit updates every page. See the next section.

4. The build script

build.py needs Python 3 and nothing else. Run it from the template/ folder:

python3 build.py

All ten pages rewrite with the shared header and footer intact. What lives where:

Thing to changeWhere
Navigation itemsNAV list
IconsI dictionary of inline SVG
Header, drawer, CTA buttonheader()
FooterFOOTER
The closing call-to-action bandcta_band()
Page titles and meta descriptionsPAGES list at the bottom
Section copyThe per-page constants: HOME, ABOUT, BENEFITS_PAGE and so on
Partner names, plans, quotes, roles, posts, FAQsThe lists above each page constant

Adding a page

  1. Write the page's sections as a new string constant.
  2. Add a tuple to PAGES: filename, title, meta description, that constant.
  3. Add it to NAV if it belongs in the header.
  4. Run the script.

5. Design system

Every token is a custom property at the top of assets/css/style.css. Change it there and all ten pages follow.

Colour

TokenValueUsed for
--blue#1B6DF0Primary actions, links, accent words
--blue-deep#0B45C4Gradient base, small text on tinted pills
--blue-tint#E9F1FEEyebrow pills, icon tiles
--blue-wash#F5F8FEAlternating sections, form fields
--ink#0B1220Headings
--ink-soft#46506BBody copy
--muted#626D87Secondary and caption text
--line#E7EBF3Card hairlines
If you change a colour, re-check contrast. The palette was tuned so every text element clears WCAG AA against what actually renders behind it, including gradients. Lightening --muted or the gradient stops is the quickest way to undo that.

Type

Plus Jakarta Sans (600/700/800) for headings and figures, Inter (400/500/600/700) for body and UI, both from Google Fonts. Sizes are fluid via clamp(), so the scale holds from 320px to 1440px without a single font-size media query.

Shape and breakpoints

Radii are 10 / 16 / 22 / 30px plus fully rounded pills. Layout breakpoints sit at 1180px (nav spacing), 980px (drawer takes over), 620px and 420px.

6. Animation

EffectHook
Scroll reveal.reveal, plus --left, --right, --scale
Stagger delay--rd, set per element in JS
Counting figures.stat b, .fcard__stat b, .trusted h2 em
Hero parallax--par on .hero__stage
Scroll progress bar.progress, injected by JS
Back to top.totop, injected by JS

Repeated items — cards, stats, table rows, timeline entries, FAQ items — are promoted to reveal targets in JavaScript rather than in the markup, so build.py can regenerate pages without losing them. Add a class to the ITEMS selector in main.js to include your own components.

To slow everything down, change the transition duration on .reveal. To remove an effect, delete its block in main.js — each is self-contained.

All of it is skipped under prefers-reduced-motion: reduce, where the counting figures render their final values immediately. Please keep that behaviour.

7. Forms and sign-up

Nothing is sent anywhere. The contact form, the email capture fields and the login and register forms are front-end only. They validate properly and show a confirmation, but no account is created and no message is delivered. Connect them before launch.

How the sign-up path is wired

The header and drawer "Get started" buttons open register.html. The hero and CTA email fields hand their address over as register.html?email=…, and the register form reads that parameter and prefills it.

To point the capture fields at a different page, set a global before main.js loads:

<script>window.FINBOLT = { registerUrl: "/signup" };</script>
<script src="assets/js/main.js"></script>

Connecting a backend

Each form's submit handler lives in main.js: search for data-demo-form (contact), data-capture (email capture) and data-auth (login and register). Validation runs first; replace only the success branch with your own fetch(). For a hosted service instead, give the form an action and method and remove the preventDefault().

The validation rules are email shape, password length and composition, required fields and the terms box. Errors set aria-invalid and aria-describedby and report inline.

8. WordPress theme

The theme ships as a separate zip, finbolt-wordpress-1.0.0.zip.

Install

  1. Appearance → Themes → Add New → Upload Theme. Choose the zip, Install, then Activate.
  2. Appearance → Menus: create a menu, add your pages, assign it to Primary (header and drawer). Until you do, the header falls back to the page list the design ships with.
  3. Create a page per template and set it under Page Attributes → Template.
  4. Settings → Reading: set a static homepage and point Posts page at an empty page called Blog. The homepage picks up front-page.php on its own.
  5. Appearance → Customize → Finbolt theme for brand, colours, buttons and footer.

Templates

FileServes
front-page.phpThe homepage, automatically
page-templates/*.phpAbout, Benefits, Testimonials, Career, Support, Contact, Log in, Register — assign per page
index.phpBlog index, from real posts
single.phpOne post, with comments
page.phpAny page without one of the templates above
archive.php, search.php, 404.phpArchives, results, not found
template-parts/post-card.phpOne card in the post grid

How links resolve

The static pages link each other as about.html. In the theme those become finbolt_link( 'about' ), which looks for the page using that template, then a page with that slug, then falls back to /about/. So cross-links keep working whatever you name the pages.

Login and register in WordPress. Those two templates are the design's front-end forms and create no accounts. WordPress has its own authentication — to use it, set the customizer's button and log-in links to your registration URL and wp-login.php.

10. Elementor

The theme is built to be edited with Elementor rather than merely to tolerate it. Four things are wired up.

A full-width builder template

Create a page, then Page Attributes → Template → Finbolt — Elementor (full width). It renders the header and footer and hands Elementor everything between them, with no heading band, no section padding and no card frame.

Why it drops the card. The design wraps every page in a 1280px card with overflow: hidden. That is what gives the site its floating look, but it also clips full-bleed sections and stops position: sticky from sticking. Builder pages get the finbolt-frameless body class, which removes the constraint so Elementor controls the full width and sticky widgets work.

For a page with no theme header or footer at all, use Elementor's own Elementor Canvas template. Elementor Full Width works too.

Theme Builder locations (Elementor Pro)

The theme registers the four core locations, so Pro's Theme Builder can replace its header, footer, single post and archive templates. Build a header in Theme Builder and the theme's own header steps aside — you will not get two.

LocationReplaces
headerThe header bar and mobile drawer
footerThe four-column footer and the bar beneath it
singlesingle.php, the whole post layout
archivearchive.php, category, tag and author listings

Widgets inherit the design

Elementor's headings, text, buttons and form fields pick up the theme's tokens, so a widget you drop in looks like the rest of the site without restyling it: pill buttons in the primary blue with the same shadow and hover lift, form fields on the wash background with the blue focus ring, headings in Plus Jakarta Sans. Elementor's boxed containers are capped at the design's --wrap width. A heading or text widget placed inside a .band section turns white automatically, so it stays readable on the blue.

All of it is scoped under the finbolt-elementor body class, near the end of the theme's style.css. Delete that block if you would rather Elementor's own defaults win.

The editor gets out of the way

The theme's scroll reveals start elements at opacity: 0. Inside a builder that would make a freshly dropped widget invisible until something scrolled, which reads as a bug. So in the Elementor editor the theme treats the page as reduced-motion: everything is visible immediately, the parallax is off, and the scroll progress bar and back-to-top button are not injected — they would otherwise float over Elementor's own panels.

Your visitors still get the full animation. It is only the editing view that stands down.

Global colours

Elementor's Site Settings → Global Colors and the theme's customizer are separate systems. Set the theme's three tokens under Appearance → Customize → Finbolt theme → Colours, then mirror them into Elementor's global palette so widgets you style there match. Whichever you treat as the source of truth, pick one.

11. Accessibility

What the template already does, and what to preserve as you edit:

  • Every text element clears WCAG AA contrast, measured against the rendered backdrop rather than the declared colour — gradients and translucent overlays included.
  • Interactive targets are at least 32px, checked from 320px up.
  • All animation is behind prefers-reduced-motion.
  • Form errors set aria-invalid and aria-describedby, and the first invalid field takes focus on submit.
  • The drawer is a labelled role="dialog" and closes on Escape.
  • Visible focus rings via :focus-visible; a skip link in the theme.
  • Decorative SVG is aria-hidden; icon-only buttons carry aria-label.
Two habits undo most of this: white text on the pale top of a gradient, and a light translucent pill behind white text — a white overlay lightens its own backdrop, which is the wrong direction. Check any new section at 320px and in a reduced-motion browser.

12. Licensing

Two products, two licences. Both ship in the HTML package's licensing/ folder.

FileGoverns
EULA.txtThe HTML template. A single-end-product commercial licence.
GPL-2.0.txtThe WordPress theme. Verbatim GNU GPL v2, also shipped inside the theme as LICENSE.
LICENSE.txtA plain-language overview of which applies where.
The EULA is a template, not legal advice. Every [BRACKETED] field needs filling in — your legal name, support terms, jurisdiction — and it should be read by a qualified lawyer in your jurisdiction before your first sale. It is written to industry convention as a sound starting point, nothing more.

Why the theme is GPL

A WordPress theme calls WordPress functions, which makes it a derivative work of WordPress, which is GPL. So the theme is GPL-2.0-or-later, and it says so in its style.css header. This is completely normal for a commercial theme — paid GPL themes are sold every day. You may charge for the files, for support and for updates. You may not stop a buyer redistributing the theme's PHP. If that is unacceptable, sell the HTML template only.

If you sell through a marketplace

ThemeForest, Creative Market and similar impose their own Regular and Extended licence terms on every sale. In that case delete EULA.txt from the package rather than shipping a second, conflicting licence.

13. Before you sell

Housekeeping worth doing once, before the first buyer:

  • Fill in the EULA. licensing/EULA.txt is a template with [BRACKETED] fields for your legal name, support terms and jurisdiction. Fill them in and have a lawyer read it. The repository's MIT licence has already been replaced with it — MIT let anyone resell the code.
  • The WordPress theme is GPL and has to be, because it calls WordPress functions. You can still charge for files, support and updates; you cannot stop a buyer redistributing the PHP. Price accordingly.
  • Replace the demo content. Every statistic, quote, job listing, blog post and partner name is invented. None of it is true.
  • Swap the favicon. Each page carries an inline SVG lightning bolt as a placeholder.
  • Update the contact details in the footer and on the contact page — the addresses, email and phone number are placeholders.
  • Point the forms somewhere, or state plainly on your sales page that they are front-end only. Buyers who discover it after purchase leave refund requests.
  • Set the theme URI and author in the theme's style.css header, which currently reads example.com.
